# Live Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Push the wipboard board to a Cloudflare Worker so it can be read from a phone, including when this machine is off.

**Architecture:** `wipboard push` serializes `build_rows` output and POSTs it to a Worker with a bearer token. The Worker stores one JSON blob in KV and server-renders a dashboard from it, leading with the snapshot's age. Cloudflare Access guards the browser route; the push path is exempt and protected by the token.

**Tech Stack:** Python 3.11+ standard library (CLI, unchanged), TypeScript Worker, Workers KV, Wrangler, Vitest with `@cloudflare/vitest-pool-workers`.

**Spec:** `docs/superpowers/specs/2026-10-20-live-dashboard-design.md`

## Global Constraints

- The CLI adds **no third-party Python dependencies**. `push` uses `urllib.request`.
- Python 3.11+, built-in generics, no `typing.List`.
- All timestamps are **naive UTC** ISO strings via `utc_now()`. Never mix in an aware datetime.
- No git invocation may raise. Any failure yields the absent case.
- `show` must never mutate the store; `push` must never touch it.
- Worker `compatibility_date` is the date the Worker is created, `workers_dev: true`, name `wipboard`.
- `observability.enabled` and `observability.traces.enabled` both `true`.
- `Env` is generated by `wrangler types`, never hand-written.
- Secrets use `wrangler secret`. No token in `wrangler.jsonc` or any tracked file.
- Secret comparison uses `crypto.subtle.timingSafeEqual` over SHA-256 digests of both values, never `===`.
- Payload `version` is `1`.

## Review Focus

Five conditions the spec implies but does not pin. Each has a test added to the task that owns the code.

1. **A project name, note or commit subject containing HTML** (`<script>`, `&`, `"`). The Worker renders server-side into HTML; unescaped it breaks the page or injects script. Task 5.
2. **A commit with an empty subject.** `--format=%cI%n%s` then splitting yields one part, not two. An index into the second part raises and takes the whole board down. Task 1.
3. **`generated_at` in the future** (clock skew, or a VM resuming). Age must read as "just now", not "-3m ago". Task 5.
4. **KV holding a `version` the Worker does not know**, because the CLI was upgraded and the Worker was not. `GET /` must say so rather than render half a page or throw. Task 5.
5. **Non-ASCII in a project name or commit subject.** It must survive JSON transport and reach the page as the right characters, which needs an explicit charset on the response. Task 5.

- [ ] **Step 3: Implement the ingest route**

`POST /api/board` only; any other method or path falls through to Task 5's router or 404.

Order matters and is the security property: check `Content-Length` and return 413 before
reading the body, then compare the bearer token, then parse and validate `version`. Compare
with `crypto.subtle.timingSafeEqual` over SHA-256 digests of the presented and expected
tokens; do not short-circuit on length. Write to `env.BOARD.put("board:current", body)`.

`wrangler.jsonc` carries `name: "wipboard"`, `main: "src/index.ts"`, today's
`compatibility_date`, `workers_dev: true`, the `BOARD` KV binding, and
`observability.enabled` plus `observability.traces.enabled`. Run `npx wrangler types` and do
not hand-write `Env`.

- [ ] **Step 3: Implement the renderer**

Every interpolated string goes through one `escapeHtml` helper. There is no exception: a note
is user text and the project list is read in a browser.

Age from `generated_at` to `now`, clamped at zero so clock skew reads "just now". Under an
hour renders normally, over an hour amber, over 24 hours red with wording that the machine has
probably been off. The header also shows a count per stage.

Rows render in payload order, which is already `_sort_key` order. Each shows stage, touched,
flags, note, branch, subject, changed count, and time in stage. `!` rows carry the same visual
weight they have in the terminal; the two views must not disagree about what matters.

Narrow-first layout, widening at a breakpoint. Inline CSS, no framework, no build step, no
client-side fetch.

An unknown `version` in KV renders a page saying the Worker is older than the CLI and must be
redeployed, rather than throwing or rendering a partial board.
